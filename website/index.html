Pick a genre

A few engines. Each doing its own thing.

RedGlitch bundles six engines covering the genres we personally wanted to build in. Pick one and its tools, physics, and editors come along with it.

◈
2.5D

IsoPixel

Isometric pixel art engine with depth-sorted rendering, a dynamic day/night cycle, particle systems (IsoFX), and procedural vegetation. Built for tactical RPGs and simulation games.

  • Depth-sorted tile rendering
  • Day/Night atmosphere system
  • IsoFX particle system
  • NPC behavior scripting
⬡
2D

RPG Top-Down

Systems-heavy engine with branching dialogue trees, quest management, inventory, NPC schedules, and a dynamic logic scripting runtime. Great for story-driven RPGs.

  • Branching dialogue trees
  • Quest & achievement system
  • Inventory management
  • JSON/JS logic scripts
▶
2D

Platformer 2D

Precision physics engine with AABB collision detection, smooth camera interpolation, and a frame-perfect character animator. Tight, responsive gameplay is the priority.

  • AABB collision system
  • Smooth camera interpolation
  • Frame animator
  • Visual platformer editor
⬛
3D

TopDown 3D

Top-down perspective with real 3D depth. Includes an ability system, fog of war, minimap, and full A* pathfinding. Bridges pixel aesthetics with 3D immersion.

  • 3D depth rendering
  • Ability & entity systems
  • Fog of war + minimap
  • A* pathfinding
◎
3D

FPS 3D

First-person engine with custom 3D camera, enemy AI, decal systems, and adapter-based rendering. For retro-aesthetic first-person experiences.

  • First-person 3D camera
  • Enemy AI system
  • Decal system
  • FPS3D adapter
◆
3D

Unified 3D

Multi-mode 3D wrapper (Game3DCore / Unified3DGame) sitting on top of the FPS/TopDown systems — swap between FPS, platformer, and top-down modes inside a single runtime.

  • Mode-switching core
  • Shared camera & physics rig
  • FPS / Platformer / TopDown modes
  • Cross-mode entity contracts

Kai — the built-in AI

A small AI helper, no cloud needed

Kai is a local assistant that runs in your browser with WebGPU/WASM. It answers questions about your project and can edit files directly, without sending anything off your machine.

⚡
Local inference

Powered by Transformers.js running on WebGPU/WASM. Everything executes on your hardware.

◎
Project-aware RAG

Kai indexes your project files, logic scripts, and engine documentation using a local vector store (Orama) for context-aware answers.

⚙
Agentic capabilities

Kai can create files, modify logic scripts, and perform tasks inside your project — not just suggest them. Tool calls are tiered by risk and gated by a permission layer.

◆
100% private

No cloud, no telemetry, no API subscriptions. Your project code never leaves your machine.

Side project

An experiment: prompt to project

ProjectVertex is a separate project that sits next to RedGlitch. You type something like "a simple platformer game," it runs a cloud LLM through a few phases, and it outputs a playable RedGlitch project — a level, entities, a campaign wrapper.

It's stateless by design: no local Cortex dependency, just plain API calls to whatever provider you point it at. That's also what makes it easy to run on Vercel if you want to deploy it there.

How it works

A handful of steps, nothing fancy

Each run walks the same fixed sequence. If you ask for more than one level, it adds a quick planning step first so the levels aren't identical.

01
Concept
Picks title, theme, engine type, and difficulty from the prompt.
01.5
Level Plan
Only runs for 2–3 level requests — briefs each level with a distinct theme.
02
Scaffold
Builds the project skeleton — redglitch.json and folder structure.
03
World Level
Generates the map for each planned level, one pass per level.
04
Entity Design
Designs the entity types available for placement (enemies, pickups, NPCs).
05
Entities
Places designed entities into each generated level.
06
Logic
Generates node/wire logic graphs — RPG top-down engine only.
07
Campaign + Build
Links levels into a campaign, validates it, and zips the final project.
LLM providers

Bring your own API key

Set at least one provider key as an environment variable. If LLM_PROVIDER isn't set, it just uses whichever key it finds first.

OpenCode Zen
OPENCODE_API_KEY
Default provider lookup target when no LLM_PROVIDER override is set.
OpenRouter
OPENROUTER_API_KEY
Model-agnostic routing layer — swap models without changing the pipeline.
Cerebras Cloud
CEREBRAS_API_KEY
Tends to run the phases a bit faster than the others.

Where it runs

Build once, ship a few places

One command packages your game for a given target. The same project runs on desktop, web, and mobile from a single codebase.

▣

Desktop

Ships as a standalone app via Electron. Embeds the game server internally — no separate install needed.

npm run build:game "MyGame" electron
◈

Web

Serves directly from an Express static server. The same HTML/JS game runs in any modern browser.

npm run build:game "MyGame" web
▤

Android

Packaged via Capacitor. Sync assets and open Android Studio with a single command.

npm run build:game "MyGame" android
◆

iOS

Also via Capacitor. Builds the iOS project and opens Xcode ready for deployment.

npx cap open ios

Where things stand

What's verified. What isn't yet.

Straight from the last internal audit — no marketing rounding. RedGlitch is a technical alpha: substantial and tested where it counts, with a clear list of what still needs proving before beta.

Verified

  • 452 Node tests passing — AI agent loop, server routes, and engine runtime logic
  • 24 server route modules exercised by real HTTP route tests, not mocks
  • Studio build passes — Vite compiles all 1,800+ modules cleanly
  • Web export completes for the bundled demo project
  • 39 checks pass in the 3D campaign integration validator

Not yet covered by automated tests

  • Editor workflows in-browser — no Playwright/E2E suite yet
  • Electron runtime — window lifecycle, preload bridge, Cortex process management
  • Python AI backend — test files exist, not wired into CI
  • Mobile & desktop packaging — Android/iOS/installer builds are scaffolded, not build-verified here

Getting started

Three steps to a running studio

Clone it, run it, open a project. That's the whole setup.

1

Clone and install

git clone https://github.com/n0rthstar/redglitch.git
cd redglitch
npm install
2

Launch the studio

# Desktop app (Electron)
npm start

# Or in your browser
npm run server
# → open http://localhost:3000
3

Create or open a project

From the project dashboard, pick one of the included demo projects — Default Project (RPG), Platformer Demo, or Iso Pixel Demo — or create a new project and choose your engine type. Prefer to generate one from a prompt instead? Try ProjectVertex.
